# Задание 1. Контракт импорта операций

Реализуй метод `OperationCsvImporter#importOperations(Path path)`. Он читает CSV-файл с операциями Wallet Service и
возвращает `ImportReport`: отдельный список успешно разобранных операций и отдельный список ошибок строк.

На этом шаге не нужны Spring, база данных и универсальная CSV-библиотека. Используй JDK и разделитель `;`.

## Входной формат

Первая строка файла — обязательный заголовок. Его не нужно преобразовывать в операцию. Каждая следующая строка имеет
ровно пять колонок в таком порядке:

```text
operationId;occurredAt;amount;currency;type
6fe05e1a-2a70-4c50-8479-1fc0c7e9e6c2;2026-09-22T10:15:30Z;1250.00;RUB;DEPOSIT
70bcd8bd-a16a-46f7-9e6d-1a347f6d84da;2026-09-22T11:00:00Z;15.50;USD;WITHDRAWAL
```

| Колонка | Формат и смысл | Во что преобразовать |
|---|---|---|
| `operationId` | UUID операции | `OperationId` |
| `occurredAt` | момент времени в ISO-8601 UTC, например `2026-09-22T10:15:30Z` | `Instant` |
| `amount` | положительное десятичное число с не более чем двумя знаками после запятой | `Money.amount` |
| `currency` | одна из `RUB`, `USD`, `EUR` | `Currency` |
| `type` | `DEPOSIT`, `WITHDRAWAL`, `TRANSFER_IN` или `TRANSFER_OUT` | `OperationType` |

Не добавляй кавычки, экранирование или многострочные поля: это намеренно упрощённый учебный формат. Пустая строка после
заголовка тоже считается некорректной строкой.

## Что нужно сделать

1. Проверь `path` на `null`.
2. Открой файл и прочитай его построчно. В задании 3 чтение будет переведено на `try-with-resources`; пока можешь
   выбрать понятный промежуточный вариант.
3. Пропусти заголовок и начинай нумерацию данных с `2`, поскольку первая физическая строка файла — заголовок.
4. Для каждой строки раздели значение по `;` так, чтобы не потерять пустые последние колонки.
5. Если строка корректна, создай `ImportedOperation` и добавь её в `operations`.
6. Если строка не может быть преобразована, не прекращай импорт: добавь `ImportIssue` с физическим номером строки,
   названием проблемного поля и коротким нейтральным описанием. Затем обработай следующую строку.
7. Верни один `ImportReport` после обработки всего файла.

Для неверного количества колонок используй поле `line`. Для ошибки даты — `occurredAt`, суммы — `amount`, валюты —
`currency`, типа — `type`, идентификатора — `operationId`.

## Границы этого шага

Сейчас важен контракт частичного успеха. Сценарий, когда сам файл отсутствует или недоступен, будет формализован во
втором задании через `OperationImportException` и сохранённый `IOException` как причину. В задании 3 в отчёт добавится
время импорта через `Clock`. Не добавляй эти части заранее, если выполняешь задания последовательно.

## Критерии готовности

- Две корректные строки дают две операции и пустой список `issues`.
- Одна повреждённая строка не мешает импортировать корректные строки до и после неё.
- `ImportIssue` содержит правильный физический номер строки и название поля.
- `ImportReport` не позволяет изменить свои списки после создания.
- Для суммы не используется `double` или `float`; создаётся `BigDecimal` из строкового значения.

### Подсказка для теста

Сделай временный файл с заголовком и несколькими строками, вызови импортёр и проверь содержимое `ImportReport`. Не
проверяй только текст ошибки: номер строки и поле — устойчивый контракт для тестов и для будущего API.
